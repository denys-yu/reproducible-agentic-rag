# ADDENDUM — _LABELLED_LINE_RE single-source-of-truth fix
########################################################################################

DEFECT: the observer hard-coded ':' while the parser's llm._DELIMITERS is '[:—–-]'.
gpt-4o-mini used an em-dash (U+2014) at the free/synthesize node on all 750 calls, which
the parser read as labelled fields (parse_status ok 750/750) while the observer reported
'prose'. The earlier free/synthesize prose=750 cell was an artifact of that regex, not a
behavioural difference in the model.

FIX: provenance._LABELLED_LINE_RE (a module constant) is replaced by
provenance._labelled_line_re(), an lru_cache(1) factory that lazily imports
llm._DELIMITERS and interpolates it. Lazy because llm imports provenance; a module-level
import would close the cycle. Whitespace after the delimiter is required, so a hyphenated
first word ('Multi-word answer') cannot read as a label named 'Multi'.
The delimiter class now has exactly one home: llm._DELIMITERS.
